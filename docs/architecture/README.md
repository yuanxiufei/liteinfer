# 架构说明

> 待 G0 / G1 产出后填写。此处只登记要产出哪些材料。

必备产出：

- `overview.md`：分层图（领域层 → 适配器 → 后端 → 服务接口），说明哪些层不允许互相反向依赖。
- `task-lifecycle.md`：任务状态机（提交、排队、运行、成功、失败、取消、回收）与每种转换的触发者。
- `resource-model.md`：显存配额、租约、借用与双缓存预算的关系；明确"配额不等于硬隔离"。
- `training-boundary.md`：LiteInfer 训练侧职责 vs 已验证底层训练执行路径的职责。

纪律参考：

- `core/` 不直接依赖 SGLang、具体 PyTorch 模型类或 Web 框架。
- 业务逻辑不放入 HTTP 控制器，也不塞进后端封装。
- 后端替换必须能在接口层完成，不得因替换一个模块推倒整个框架。
