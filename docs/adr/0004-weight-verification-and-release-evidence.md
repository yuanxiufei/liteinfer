# ADR-0004：权重校验强度与释放证据口径

- 状态：accepted（已随 WBS-2 实现落地）
- 日期：2026-10-29
- 相关：ADR-0003（依赖边界）、G2 前置验收条件

## 背景

WBS-2.6 / 2.7 要回答两个可操作的判断问题：

1. 权重"校验通过"到底意味着什么？全量哈希很慢（4TB 盘上的大模型），
   不验又会把损坏权重当成有效模型——后者是 G2 前置条件明令禁止的。
2. 适配器释放后怎么证明资源真的回落了？Python 对象被删除 ≠ 显存被释放。

## 决策

### 1. 校验分三档，但**没有"大概能用"这一档**

| 项目 | 默认 | 说明 |
|---|---|---|
| 存在性与可读性 | 强制 | 缺失/不可读直接判失败 |
| 大小一致 | 清单给了就强制 | 清单没给 `size_bytes` 就不比对 |
| SHA-256 | 清单给了就强制；未给由 `require_sha` 决定 | 分块 1 MiB 流式计算 |
| 格式已知 | 默认强制 | `allow_unknown_format=True` 才放行 |

结果只有 `ok` 或明确失败状态（`missing` / `unreadable` / `size_mismatch` /
`hash_mismatch` / `unknown_format`）。**空清单不算通过**——没有权重就没有模型。

取舍：默认不做全量哈希是为了不拖慢启动，但"清单里写了哈希就必须验"这条是硬的；
要求强校验的场景用 `require_sha=True` 显式打开，不做隐式策略。

### 2. 释放必须有可观测证据

每次真正卸载（引用计数归零）都留一条 `ReleaseRecord`：
`released_at` / `refcount_after` / `unloaded` / 释放前后资源采样 / 失败原因。

- 采样器由外部注入（WBS-3 接 NVML），拿不到采样时记录 `None` 或 `{"error": ...}`，
  **不允许"什么都没记就算释放成功"**。
- 没有注入卸载器时 `unloaded=False`——不能假装卸载成功。
- 卸载抛异常也要留证（`error` 字段），不吞掉。

### 3. 采样失败不掩盖释放流程

`sampler` 抛异常只影响证据质量，不影响生命周期推进；
证据里如实记 `{"error": ...}`，便于事后区分"释放失败"与"采样失败"。

## 影响

- 好处：损坏/被替换的权重不会静默通过；释放是否真的回落有据可查。
- 代价：清单里给了哈希就必须付出哈希时间；释放路径多一次采样开销。
- 后续：WBS-3 把 NVML 采样接进 `WeightStore` 的 `sampler`；
  WBS-4（Swap）与 WBS-5（LoRA）复用同一套引用计数与证据结构。
